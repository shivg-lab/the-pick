# Implementation plan

The repository started empty. Python 3.12, a local Node LTS runtime and Ollama are the development prerequisites.

1. Typed domain models and interchangeable providers; illustrative inventory with explicit provenance.
2. Eligibility, hard constraints, distance, deterministic scoring and confidence; test these before UI integration.
3. Ollama schema-constrained intent and bounded observation-driven tool selection, plus source-ID-only grounded explanations.
4. Curated official-source corpus, persistent local cosine vector index, venue metadata isolation and policy precedence.
5. FastAPI recommendation persistence, status, activity streaming and feedback.
6. Mobile-first editorial interface with search, results, comparison and venue guide.
7. Unit, integration, failure and browser tests; run genuine Ollama scenarios and record evaluation limitations honestly.
8. Clean-checkout setup, architecture, troubleshooting, Docker and competition script.

Demo is a seasonal sampler: September and November 2026 dates and prices are authored examples, never verified fixtures. Stored venue summaries are independently sourced. Hybrid excludes illustrative records and needs verified curated enrichment for competitive signals. No secrets or model weights belong in version control.
